# 交接信（Handoff Letter）

DSH 会话没有跨会话记忆：新会话的一切"了解"都来自外部注入（AGENTS.md、工具、磁盘）。
交接信就是把"我这一代的经历"变成下一代的外部注入——给下一代留的信。
**本技能零依赖：只用文件系统，任何 stock DSH 都能用。**

## 何时写交接信

- **用户点名**：说"写交接信 / 交接文档 / 遗书 / handoff"时
- **上下文将尽**：察觉上下文接近耗尽（回复开始吃力、历史被裁剪）时主动提出并写入
- **高风险操作前**：升级 DSH、大重构、批量删除/迁移数据之前，主动写
- **阶段性收尾**：长任务告一段落、用户要下班/换设备时

## 写到哪里

文件各司其职，**AGENTS.md 只做"引子"不放内容**（它每轮都被注入，保持精简）：

| 文件 | 角色 | 谁写 |
|---|---|---|
| `HANDOFF.md` | 交接信本体：进度、结论、雷区、接力点 | 每代会话重写 |
| `MEMORY.md` | 长期记忆：跨会话成立的事实，一行一条只增不删 | agent 自我维护 |
| `SOUL.md` | 人格设定（养崽/角色时用） | 用户主导 |
| `AGENTS.md` | **引子**：规则 + 指向上面三个文件的指针 | 技能首次运行时补齐 |

- **主信**：`<当前工作区根目录>/HANDOFF.md`——下一代在同一工作区开工时第一眼能看到
- **耐久事实**：追加到工作区 `MEMORY.md`（不存在则新建），格式 `[YYYY-MM-DD] 事实`；只增不删，超过 100 行时把最旧的 50 行压缩成摘要段
- **引子维护**：检查工作区 `AGENTS.md`，若没有指向 HANDOFF/MEMORY/SOUL 的"会话启动"小节就补上（模板见下）；**不要把记忆内容写进 AGENTS.md**——它是每轮注入的目录页，不是仓库

## 怎么写

**重写而非追加**：每代一封新信（可保留"族谱"小节链接历代）。写给"完全不知道前情、但和你能力相当的下一代"——不省略关键上下文，不堆流水账。模板：

```markdown
# 交接信 · 第 N 代（YYYY-MM-DD HH:mm）

## 一句话现状
<现在处于什么状态，下一步就差什么>

## 已完成（含关键产物路径）
- <做了什么，产物文件的绝对路径>

## 关键发现与决定（为什么这么做）
- <技术结论、踩过的坑、选 A 不选 B 的理由>

## 未竟事项 / 雷区
- <没做完的、验证过的死路、不能碰的东西>

## 环境备忘
- <工具路径、命令、账号/登录态等耐久事实>

## 给下一代的话
<自由发挥>
```

## 会话开始时（读信）

1. 开工前检查当前工作区根目录是否存在 `HANDOFF.md`（或用户提及"上一代的信"）
2. 存在就先读完再行动；在回复开头用一两句说明"已读第 N 代的交接信，当前接力点是 X"
3. 使命完成后：更新或归档（重命名为 `HANDOFF.gen-N.done.md`）旧信，避免下下代误读过期状态

## 养人格/养崽玩法（可选）

想长期养一个"人格"（比如 QQ 机器人、专属助手），用引子模型三件套：
1. 工作区放 `SOUL.md`（人格设定）+ `MEMORY.md`（它的记忆）
2. 工作区 `AGENTS.md` 里写入引子规则：

```markdown
## 会话启动（agent 必读）
1. 存在 SOUL.md → 先完整阅读，它是你的人格
2. 存在 HANDOFF.md → 先读，那是上一代的接力点；完成后归档为 HANDOFF.gen-N.done.md
3. 记忆在 MEMORY.md，需要背景时自己去读

## 记忆维护（agent 自我执行）
- 重要事件/结论/用户偏好出现后，往 MEMORY.md 追加一行：[YYYY-MM-DD] 事实
- MEMORY.md 只增不删；超过 100 行时把最旧的 50 行压缩成一段摘要
```

3. 每个新会话都会按引子自动"夺舍"同一个人格——人格住在文件里而不是会话里，升级、丢会话都不怕
